# Задание 5. Разработка cutover-плана

## Выбор стратегии миграции

Хотя как таковой системы нет, а есть только ручные процессы с файлами Excel, выбираю стратегию Parallel Run - параллельный запуск старой и новой систем с постепенным переводом нагрузки.

Обоснование стратегии Parallel Run:

1. Нет гарантии, что удастся одновременно переключить всех сотрудников. В этом случае во время миграции часть данных будут обрабатывыться по старой схеме. 
2. Не можем остановить бизнес-процессы: пациенты записываются, ведется прием, параллельная работоа обеспечит непрерывность бизнес-процессов.
3. Если что-то пойдет не так, можно будет без ппотери данных и с минимальным простоем вернуться на исходную схему (план отката).
4. Возможно поэтапное обучение пользователей новой системе, на обучение всех сотрудников и курирование миграции нет столько людских резервов.

Почему не подходят другие стратегии:

1. High-level design:

   - возможны простои при миграции, если придется откатывать, нужно будет обратно мигрировать данные;
   - не предусмотрена поэтапная или частичная миграция, переключаем всех сразу;

2. Branch by abstraction:

   - не подходит, поскольку предполагает наличие старой кодовой базы, а ее нет. Невозможно добавить программный слой абстракции над ручными процессами с Excel-файлами или поверх 1С, код которой мы не трогаем;

## Cutover-plan

Считаем, что:
1. Cистема разработана;
2. Система развернута в тестовом контуре;
3. Система протестирована и принята в опытную эксплутацию;
4. Разработана программа обучения.
